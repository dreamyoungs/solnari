# PostgreSQL 실행 결과와 권한 검증

행이 없는 DDL·권한 변경 및 트랜잭션 실행은 명령 결과 패널에 명령, 영향받은 행 수,
트랜잭션 상태를 표시합니다. 조회 결과가 있으면 마지막 표를 유지하고 **Messages**에서
명령 목록을 봅니다. 명령 실행 성공과 실제 권한 상태 검증은 별개의 결과입니다.

## 트랜잭션

- Cloud SQL: PostgreSQL simple-query의 여러 결과를 처리합니다. `COMMIT` 뒤에도 마지막
  조회 결과를 보존합니다. 서버가 보고한 idle/open/aborted 상태와 COMMIT/ROLLBACK 결과를
  구분합니다. 중간 오류 시 DB 오류·SQLSTATE·문자 위치와, 해석 가능한 경우 문장 번호를
  표시합니다. 열린 실패 트랜잭션은 사용자가 `ROLLBACK`으로 종료해야 합니다.
- Direct/SSH/Kubernetes: 하나의 완결된 `BEGIN … COMMIT` 또는 `ROLLBACK` 스크립트를
  동일한 물리 연결에서 순서대로 실행합니다. 중간 오류 시 같은 연결에서 ROLLBACK하고
  문장 번호와 실제 롤백 결과를 표시합니다. 여러 번의 클릭에 걸쳐 트랜잭션을 열어 두는
  작업, 중간 커밋, AND CHAIN, SQL 함수의 인용되지 않은 BEGIN ATOMIC 본문은 지원하지
  않습니다. 인용·주석이나 escape 해석이 모호한 스크립트는 실행 전에 거부합니다.
- 결과 크기·인코딩 제한 때문에 Cloud SQL PostgreSQL 결과를 표시하지 못해도 DB 실행
  성공은 유지하고 재실행 전에 상태를 확인하도록 안내합니다. 표 결과는 마지막 하나만
  표시하며 명령 목록은 최대 1,000개입니다.
- Cloud SQL 경로의 서버 notice/warning은 명령 성공과 별도로 표시합니다. 네이티브
  드라이버가 제공하지 않는 notice나 상태를 확인한 것으로 표시하지 않습니다.

## 권한 검증

PostgreSQL GRANT/REVOKE 실행 전 조회 가능한 역할 membership과 시스템 스키마를 제외한 테이블 권한을 메모리에
기록합니다. **권한 검증** 버튼은 고정된 읽기 전용 카탈로그 조회로 전후 추가·제거를
표시합니다. 결과는 최대 1,000행이며 초과하거나 조회가 실패하면 검증 불가로 표시합니다.
다른 세션의 변경도 비교에 포함될 수 있습니다. 컬럼·함수·스키마·기본 권한이나 사용자가
의도한 효과 전체를 검증한 것으로 표시하지 않습니다. SQL을 다시 실행하거나 재접속하면
기존 비교 기준을 폐기합니다. SQL·notice·원본 DB 오류를 진단 로그나 MCP 오류에 넣지 않습니다.

기존 MCP 쓰기 지원은 유지합니다. 연결의 Read / Write 권한과 재접속이 필요하고,
상태 응답과 구조화된 거부 응답에서 사용할 도구와 다음 단계를 안내합니다.
